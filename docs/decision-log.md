# Dubbing MVP decisions

2026-10-15, 0.5.2: The owner resumed work and requested romaji, pinyin and Korean readings. Pronunciation runs in the existing local Python worker with pinned dictionaries. A saved display preference chooses original/both/Latin views; original text and measured word times remain authoritative. Contextual Japanese pronunciation uses fugashi/UniDic before Latin conversion, Mandarin uses tonal phrase pinyin, and Korean uses Revised Romanization. Manual readings are retained and can be reset one line at a time. Automatic character subdivisions are approximate and manual readings use line timing. New dictionary/license data ships with the runtime. No translation service or application network request is introduced.

2026-10-15, 0.5.1: The owner prioritized late recorded singing and inconsistent lyric timing before the GitHub installer work. Singing capture now uses PCM samples stamped on the backing track's AudioContext, with reported input/output latency compensation and a compensated recording tail. The FFT denoiser's measured 25 ms content delay is removed and its tail flushed in both saved takes and clip effects. Existing take files are retained; selected-take alignment is saved separately and shared by playback and cover export. Song-wide lyric timing remains independent. Measured word spacing survives line moves/resizing; new transcripts use short phrases based on word times. No new dependency or model is required. Device estimates can omit hardware delay, so this is not represented as physical-device calibration. Details and evidence: singing-timing.md.

2026-10-15, 0.5.0: The owner requested a CapCut-like Professional workspace alongside Easy mode, Ctrl+B split with configurable shortcuts, individual audio processing/fullscreen preview and explicit Dub 1–4 for simultaneous speakers. The existing Electron/FFmpeg stack remains. Split pieces reuse each parent recording and store independent timing/effects/track placement. Persistent voice tracks distinguish recording groups, so a retake does not deselect another speaker. Original audio and video have separate editable ranges; edited video previews are generated before accepting a visual edit. A shared validated effect configuration drives the inspector and all audio renders. Undo restores timeline state without deleting recording files; history is session-local. No dependency or cloud service is introduced. Source preservation, multi-voice output, actual effect processing, playback alignment and UI regressions are tested with generated media in isolated profiles. See professional-mode.md for behavior and limits.

2026-10-14, 0.2: The owner requested a simple Choicer Voicer-style per-part review flow, modern blue Aero scenery, audible-region cutting with 1–3s context, stronger dubbing volume and an app-surface Ctrl+A guard. The current flow is upload -> Start dubbing -> record/check/retake current part -> explicit Next -> full review -> export or return to a specific part. Older take files remain available.

- Sound activity is detected with FFmpeg silencedetect; quiet gaps define cores, 1.5s context is the default, and overlapping context is clipped at the midpoint. This is not speech/character detection. Continuous sound has a 12s phrase fallback.
- Global dub gain 0–4 multiplies per-take gain consistently in take audition, full preview and export. The former HTMLAudio volume clamp is replaced by a rendered audition with the same limiter.
- Local media now serves real byte ranges with 206/Content-Range; simply forwarding file fetches could restart seeking playback at zero and capture earlier portions again. Seven later-part captures and exports verify the corrected timebase.
- Recordings stay on the current part for review. Next is explicit, and the full review keeps part navigation so retakes affect only that part.
- Background mountains are original SVG; the sparse CSS bubbles are explicitly requested and hidden with reduced motion. Body selection is disabled while text fields and a dedicated copyable status retain selection.

2026-10-14: The owner explicitly requested implementation now, with working dubbing prioritized over the planning kit's full release scope. The kit's planning-only pause was therefore superseded by this request.

- Electron + plain local HTML/CSS/JavaScript keeps the first complete dubbing workflow small. React, a Python server, and model runtimes are unnecessary for recording and deterministic mixing.
- FFmpeg/FFprobe run as supervised subprocesses with argument arrays and cancellation. No shell commands are accepted from the renderer. A sandboxed, isolated preload exposes specific IPC operations only.
- Source video remains unchanged. A silent H.264 proxy drives the editing clock; the extracted reference audio shares its timeline. Output uses the original video stream where MP4 compatible.
- Recording uses MediaRecorder and browser microphone noise suppression/echo cancellation when Clean microphone is enabled. Measured capture lead is trimmed before placing a take. Fine alignment remains editable in milliseconds. Physical device latency calibration is deferred.
- The owner's added noise-cancelling request is implemented with capture suppression and a separately saved high-pass/afftdn/low-pass cleaned version. Cleanup can be disabled per take. The capture suppression itself is baked into the captured recording.
- The same FFmpeg mix graph drives preview and export. Original audio ducks only during selected, unmuted takes. Dialogue isolation and music stem separation are explicitly deferred.
- UUID-scoped project directories retain raw/clean audio and versioned metadata. Autosave uses temporary JSON followed by rename; import/export cancellation does not replace the source or completed destination.
- Aqua Glass Studio comes from the supplied brand direction. Original CSS provides the satin chrome; there are no downloaded visual or sound assets.
