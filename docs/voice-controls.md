# Universal own-voice control 0.4.2

The 0.4.2 low-input fix defaults Auto microphone level on. A single captureConstraints helper supplies microphone testing, dubbing and singing: selected device, preferred mono, optional browser noise suppression, echoCancellation false and autoGainControl following the saved checkbox. The checkbox locks during capture and restarts an active test mic after a change. Older settings missing the field use true; false survives saved settings. The browser/device must support the requested automatic level; this is not a fixed software boost or a guarantee of identical loudness on every microphone. Manual voice gain remains independent.

The former cleanup combined noise reduction 12dB with an assumed noise floor of -35dB. On an original synthesized speech fixture attenuated to quiet-microphone level, active top-20%-window RMS was -47.25dBFS raw, -57.41dBFS through the previous filter and -47.89dBFS through the new filter (9.52dB more retained). The new chain keeps the 75Hz high pass and 14kHz low pass, uses afftdn nr=6:nf=-55 and compensates limiter latency. A self-contained pulsed quiet speech-band fixture verifies at least 75% amplitude retention, preserved duration and silence staying quiet; existing rumble-removal checks still pass. Test/diagnostic audio is local under test-output, excluded from the app. No original user project/take is reprocessed.

Settings contains volume 0–4, gain -24..24 dB, bass/treble -12..12 dB and pitch -12..12 semitones. A shared whitelist validates finite bounded values at settings/capture IPC boundaries. Settings persist globally; each new video/song take records its own preset. Neutral effects leave captured audio unchanged. Existing takes are never reprocessed by changing the global settings.

Hear my voice obtains the selected microphone and feeds a local Web Audio graph: low shelf at 200Hz, high shelf at 4kHz, combined volume/dB gain, direct or SoundTouchJS AudioWorklet pitch path, dynamics limiter, input meter and optional monitor output. Neutral pitch bypasses the time-stretch path. Parameter changes ramp over 20ms. Monitoring defaults off at launch and remains switchable during capture; effect sliders lock until the take finishes. Closing/changing the mic disconnects its graph and closes its owned context. Singing reuses its playback context and releases only the mic graph. Countdown cancellation and capture-init failure release the microphone.

MediaRecorder captures the original browser microphone stream so monitoring/pitch latency cannot shift the saved timeline. FFmpeg processes the decoded 48kHz mono capture using bass/treble, gain, pitch resampling plus reciprocal tempo correction, and a limiter. Both raw and noise-cleaned variants receive the preset once. Tail padding/trimming preserves the original capture duration; the existing video/song lead trimming then preserves take alignment. Audition/export consume those processed files without applying the preset twice. Raw here means the variant without optional FFmpeg noise cleanup, not the original pre-effect capture. Live and rendered DSP use the same settings but are not sample-identical.

Tests use fake microphone audio, isolated profiles and invisible noninteractive windows. The voice UI checks actual spectrum change from about 1200Hz to 2400Hz, monitor on/off, all five saved values, reset, all languages and narrow layout. Video/song UI tests verify the preset metadata and measured octave shift in the actual captured take, plus preview/export/cleanup. Backend tests measure gain and low/high shelf changes, octave pitch and preserved duration/source bytes. Physical microphone monitoring latency and subjective voice quality remain unmeasured.

0.4.2 checks additionally verify the shared capture requests, automatic-level default, live off/on restarts, saved setting, invalid IPC rejection, independent echo/noise flags, mono preference and recording-time lock. Singing verifies the actual requested track constraints. The user's settings were read only for diagnosis: their volume was 100%, gain 0dB and tone/pitch neutral. Physical-device AGC behavior and the user's current spoken level cannot be inferred from fake-input tests.
